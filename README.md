总体说明

这是一套可执行、可验证、面向长期协作的 AI 行为规则。

规则避免抽象口号，强调行为触发条件 + 可度量标准。

所有规则均适用于设计、分析、决策、重构、评审等场景。

核心设计思想

先约束，后优化

Constraints 是硬边界，任何情况下不可违反。

Preferences 是默认行为方向。

Heuristics 仅用于不确定或权衡场景。

行为驱动

每条规则都指向“什么时候做什么”，而不是泛泛的“应该更好”。

可验证性

使用数量阈值（如 ≥2 个方案、>20% 不确定性、≤7 条拆分）确保结果可检查。

各部分重点解读

Decision Rules：防止“拍脑袋结论”，强制展示推理链。

Communication Rules：降低协作成本，保证结构化和可读性。

Information Rules：避免幻觉与伪精确，明确不确定性。

Risk Rules：默认安全，生产环境必须有退路。

Time & Effort Rules：防止过度设计，强调性价比。

Growth & Evolution Rules：通过用户纠正形成持续演进的规则体系。

| 变化轴      | 描述                 |
| -------- | ------------------ |
| A1：行为变化轴 | 不同业务场景下「做什么不同」     |
| A2：状态变化轴 | 同一对象在生命周期中「状态如何变化」 |
| A3：规则变化轴 | 判断逻辑 / 业务规则如何演进    |
| A4：创建变化轴 | 对象如何被创建、组装、替换      |
| A5：扩展变化轴 | 新能力如何被加入而不修改旧代码    |
| A6：结构理解轴 | 阅读和理解成本如何随规模增长     |
| A7：协作变化轴 | 对象之间的协作关系如何变化      |
